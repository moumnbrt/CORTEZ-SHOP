# متجر كورتيز (CORTEZ SHOP)

متجر افتراضي لعالم تمثيل الأدوار (RP)، بواجهة عربية فصحى واتجاه RTL، وتصميم مستوحى من صورتك (خلفية سوداء مع نيون وردي `#F107A5` وسماوي `#61EDFB`).

## المميزات

- تسجيل الدخول عبر ديسكورد (OAuth2).
- التحقق تلقائياً من رول «شوب» في السيرفر؛ من لا يملكه لا يستطيع دخول المتجر.
- لوحة تحكم لإضافة المنتجات وتعديل السعر والكمية وحذفها، ومتابعة الطلبات وتغيير حالتها.
- وضع تجريبي يجعل experimentation ممكنة بدون بيانات ديسكورد.
- حفظ البيانات في ملف `data/store.json` (لا يحتاج قاعدة بيانات).
- صلاحيات عرض مفصولة:
  - **القانق (عضو برول شوب، غير أدمن):** يرى «المتجر» و«طلباتي» فقط، وطلباته الخاصة فقط.
  - **الأدمن (`ADMIN_DISCORD_IDS`):** يفتح مباشرة على لوحة تحكم بمنظور `ROOT` (كونسول، إحصائيات، سجل أحداث، قائمة الأعضاء)، ويرى **كل طلبات القانق** المسجّلة داخل السيت مع اسم صاحبها.

> ملاحظة: منع الوصول مُطبّق في الخادم أيضاً؛ محاولات الدخول المباشر إلى نقاط الإدارة من عضو عادي تُرفض برمز 403. الأدمن لا يحتاج رول «شوب»، إذ يُمنح الوصول تلقائياً بمجرّد تطابق معرّفه مع `ADMIN_DISCORD_IDS`.

## التشغيل محلياً

```bash
npm install
npm run dev
```

افتح `http://localhost:3000`. ما لم تضبط بيانات ديسكورد، سيعمل الموقع تلقائياً في الوضع التجريبي: اضغط «تسجيل الدخول عبر ديسكورد» وستدخل بحساب تجريبي له صلاحية المتجر والإدارة.

## معاينة المناظر (محلياً فقط)

عند `PREVIEW_MODE=true` (وهو مفعّل في `.env` الحالي، ومعطّل تلقائياً في الإنتاج) يمكنك فتح روابط مباشرة لرؤية الموقع بكل منظور دون حساب ديسكورد إضافي:

- `http://localhost:3000/auth/preview?as=member` — منظور القانق: المتجر + طلباته فقط.
- `http://localhost:3000/auth/preview?as=admin` — منظور الأدمن: لوحة `ROOT` وكل الطلبات.
- `http://localhost:3000/auth/preview?as=denied` — صفحة «الوصول مقيد» لمن لا يملك الرول.

> هذه الروابط معطّلة تماماً على Render لأن `NODE_ENV=production`.

## إعداد ديسكورد

1. افتح [Discord Developer Portal](https://discord.com/developers/applications) وأنشئ تطبيقاً جديداً.
2. من **OAuth2** انسخ `CLIENT ID` و `CLIENT SECRET` وضعهما في `.env`.
3. أضف رابط التحقق: `http://localhost:3000/auth/discord/callback` (وعلى Render: `https://<اسم-التطبيق>.onrender.com/auth/discord/callback`).
4. في **OAuth2 → Scopes** فعّل: `identify`، `guilds`، `guilds.members.read`.
5. انسخ `.env.example` إلى `.env` واملأ القيم:

```bash
cp .env.example .env
```

يُحمَّل ملف `.env` تلقائياً عند تشغيل الموقع (عبر `dotenv`). معرّفا الأدمن مضبوطان مسبقاً في `.env` الحالي.

### متغيرات البيئة

| المتغير | الوصف |
|---|---|
| `PORT` | منفذ التشغيل، الافتراضي `3000` (Render يضبطه تلقائياً) |
| `BASE_URL` | الرابط العام للموقع، يُستخدم لبناء رابط التحقق |
| `SESSION_SECRET` | نص عشوائي طويل لتوقيع ملفات تعريف الارتباط |
| `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET` | بيانات تطبيق ديسكورد |
| `DISCORD_REDIRECT_URI` | رابط التحقق بعد تسجيل الدخول |
| `DISCORD_GUILD_ID` | معرّف سيرفر العائلة |
| `DISCORD_SHOP_ROLE_IDS` | معرّف رول «شوب» (أو أكثر، مفصولة بفاصلة) — الطريقة المفضّلة |
| `DISCORD_SHOP_ROLE_NAME` | اسم الرول، الافتراضي `شوب`. يُستخدم فقط عند وجود بوت |
| `DISCORD_BOT_TOKEN` | توكن بوت موجود في السيرفر، بديل عن معرّف الرول للمطابقة بالاسم |
| `ADMIN_DISCORD_IDS` | معرّفات أدمن ديسكورد، مفصولة بفاصلة |
| `DISCORD_INVITE_URL` | رابط دعوة السيرفر الذي يظهر في الواجهة |
| `DEMO_MODE` | `true` لتفعيل الدخول التجريبي؛ لا تفعّله في الإنتاج |

### كيف يعمل التحقق من الرول؟

بعد تسجيل الدخول، يطلب الموقع عضوية السيرفر عبر `guilds.members.read`، ثم يقارن رول العضو بمعرّف «شوب». إن لم تُضبط معرّفات الرول، يمكن للموقع جلب رول السيرفر عبر بوت (`DISCORD_BOT_TOKEN`) والمطابقة بالاسم «شوب». من لا يملك الرول يُعاد توجيهه إلى صفحة «الوصول مقيد».

> ملاحظة: عند تغيير رول العضو في ديسكورد، يجب عليه تسجيل الدخول من جديد حتى يتحدّث التحقق.

## تنبيه الطلبات في روم ديسكورد

عند ضبط webhook، كل طلب جديد كيتبعت للروم كـ embed فيه: الزبون، المنتج، الكمية، سعر الوحدة، الإجمالي والحالة.

الطريقة الأسهل:
1. فديسكورد، افتح **إعدادات السيرفر → التكاملات (Integrations) → Webhooks → Webhook جديد**.
2. اختر الروم اللي بغيتي التنبيه يظهر فيه، وسمّيه مثلاً `طلبات المتجر`، ثم انسخ **Webhook URL**.
3. حط الرابط فـ `.env`:
```
DISCORD_ORDER_WEBHOOK_URL=https://discord.com/api/webhooks/.../...
```
4. أعد تشغيل الموقع. إذا تركت القيمة فارغة، ما كيبعتش أي تنبيه والموقع كيخدم عادي.

> لا تشارك رابط الويبهوك، فهو بمثابة كلمة سر تسمح بالكتابة فالروم.

## النشر على Render

- ابدأ بأمر `npm start` ومنفذ `PORT`.
- أضف متغيرات البيئة أعلاه، واجعل `NODE_ENV=production` و`DEMO_MODE=false`.
- رابط التحقق يجب أن يشير إلى نطاق Render الخاص بك.

> تخزين البيانات حالياً في ملف محلي. على Render المجاني قد تُزال الملفات عند إعادة النشر؛ للاستخدام الدائم، انقل `lib/store.js` إلى قاعدة بيانات (Postgres مثلًا).

## بنية المشروع

```
server.js          نقاط النقل والصفحات
lib/config.js      قراءة الإعدادات
lib/store.js       حفظ المنتجات والطلبات
lib/discord.js     OAuth2 والتحقق من الرول
lib/session.js     جلسات موقّعة
public/            الواجهة (HTML/CSS/JS + صورة الشعار)
data/store.json    بيانات التطبيق (تُنشأ تلقائياً)
```
